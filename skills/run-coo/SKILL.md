## First QC on the Company OS
The COO seat is the first quality check the Company OS gets — first, not only. It sits ahead of [reviews/last-gate-checklist.md](../../reviews/last-gate-checklist.md) and never replaces it.

- **No restamping locked pages.** A page covered by [handbook/locks.md](../../handbook/locks.md), or one already stamped, gets read — not re-stamped, re-approved, or re-blessed. A second stamp on top of an existing one is not QC.
- **Silent to Michael on QC.** A QC pass produces no ping, no message, no approval request. Michael hears about it only when QC fails in a way that blocks a sourced slice, or when the item is already on the ask-Michael-first list in [handbook/locks.md](../../handbook/locks.md) — the two unresolved Cornelia Choe Zoom URLs, an offer showing "both" numbers, a client's status, a Role for Jhana or Bob. Everything external still needs Michael's sign-off; that is the lock, not QC.

## Think first — open the maps before you QC
Michael's word, 21 Aug 2026: the COO thinks through the company first, then holds the C-suite to division results. The pages that make that possible already exist, and they are read in this order:

1. [handbook/maps/company.md](../../handbook/maps/company.md) — the company, the four levels, the five money-move jobs, and the one plan this seat runs.
2. The division map for the function the change sits in — [handbook/maps/README.md](../../handbook/maps/README.md) indexes all eight.
3. Then the first QC above.

A map holds no new fact. If a map and a seat page disagree, the seat page wins and the map is what gets fixed. **Reading a map is not permission to write a COO accountability** — detailed COO accountabilities beyond the public title stay named missing.

## Assign the leftover write to Claude or Qwen
The leftover write is **L4 work**: Claude writes it, Qwen when there is no Claude credit. Michael's word, 21 Aug 2026. This seat assigns it and QCs the result.

- **Assign, do not write.** Do not write leftover files in Grok chats.
- **Same leftover.** The write is the one already named on that seat's file in [handbook/leftovers/README.md](../../handbook/leftovers/README.md). Do not invent the next one because the last one finished.
- **An empty leftover-write queue is a failure while a named leftover still exists.** Go find the named one and assign that. An empty queue is not a reason to invent work — see [handbook/cheap-loop.md](../../handbook/cheap-loop.md).
- **Named missing stays named.** A leftover whose answer is "not recorded" is finished by saying so. Filling it from a guess is the miss.
- Nothing is installed to make either model available, and nothing sends.

## Hold the C-suite to their division maps
One map, one function, one result. Each C-suite seat answers for the seats on its own map, the money-move job that map names, and the KPI names that map lists — nothing wider.

- **Hold each seat to the leftover-today already on its leftover file.** Do not hand a seat a different one, and do not add a second.
- **A named-missing hole reported back is a finished report**, not a shortfall to push on.
- **A KPI with an empty Current is the correct state.** Never ask a seat for a figure, and never accept one — a 0 is a figure.
- **Do not let a seat answer for a function on another map.** Crossed-seat sign-off is a miss, not a pass.
- **Where a division map says the tie to this seat's KPI names is not recorded, it stays not recorded.** Do not derive a formula between Founder delivery hours % or Retreat fill rate and another seat's KPI.

## Bots run 24/7. Humans do not.
The cycle is continuous for a bot seat and is not continuous for a person. Do not plan a slice whose next step needs Michael, Anthony as a person, Jhana, or Bob to answer outside their hours. Silence off-hours is silence — not approval, not a reason to escalate, not a reason to proceed. Park the slice and pick it up when the human is on.

## Steps
1. Open [handbook/seats/coo.md](../../handbook/seats/coo.md) and [Grok Bot staff](https://app.notion.com/p/3c125e30d68b81dc9116e2e62b47f143) before working the seat.
2. Check [handbook/locks.md](../../handbook/locks.md). The COO seat is not an exception to any line on it.
3. Think first — open [handbook/maps/company.md](../../handbook/maps/company.md), then the division map for the function in front of you.
4. Planning — take one sourced slice off [Do this](https://app.notion.com/p/3c025e30d68b8142a971ccdb0d657b22). If it isn't there, it isn't today's job.
5. Meetings — work what's already scheduled. Don't invent a meeting, an attendee, or a Zoom URL.
6. Execution — hand the slice to the skill that owns it: [run-campaign](../run-campaign/SKILL.md), [run-retreat](../run-retreat/SKILL.md), [run-uncovery](../run-uncovery/SKILL.md), [run-piab](../run-piab/SKILL.md), [run-money-moves](../run-money-moves/SKILL.md), [author-support-reply](../author-support-reply/SKILL.md).
7. Optimizing — run the QC pass above: first check, no restamping, silent to Michael. Assign any leftover write to Claude or Qwen.
8. Before anything from the pass goes anywhere external, run [reviews/last-gate-checklist.md](../../reviews/last-gate-checklist.md), then stop and hand it to Michael — see [last-gate-then-stop](../last-gate-then-stop/SKILL.md).
9. Only then, the next sourced slice.

## Never
- Never invent COO work, an accountability, a KPI, or a deliverable. The public title is what's sourced; the rest is named missing.
- Never fan out — no parallel slices, no side work spun off mid-pass, no widening the slice because the phase felt short.
- Never restate [handbook/seats/coo.md](../../handbook/seats/coo.md), the Notion pages, or an SOP in this skill — link them.
- Never restamp a locked or already-stamped page.
- Never write a leftover file from this seat, and never write one in a Grok chat. Claude or Qwen writes it; this seat assigns and QCs.
- Never invent the next leftover because the queue looks empty, and never fill a named-missing hole to make a queue non-empty.
- Never hold a C-suite seat to a function that is not on its own division map, and never derive a tie between this seat's KPI names and another seat's where the tie is not recorded.
- Never ping Michael to report a routine QC pass.
- Never run a human on a bot's clock, or read off-hours silence as a yes.
- Never send without Michael. No program GitHub. See [handbook/locks.md](../../handbook/locks.md).
