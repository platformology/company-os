## The pass

**1. Read the ask against the locks.** Open [locks.md](../locks.md) and read it against the thing actually in front of you, not against the seat in general. If a lock stops the ask, quote that lock in one sentence and stop there — you are done, see "Stops that count as finished" below.

**2. Open Do this and take the top item that is genuinely on it.** If it is not on that page, it is not today's job. Read the day's cadence off the calendar that already exists rather than asking Michael what the slots are. If the page is honestly empty, say that — "honestly empty" is a real answer, and looking busy is not.

**3. Ask whose job it is.** If the item belongs to another seat, find that seat's row in [seat-job-map.md](../seat-job-map.md), hand it the router in that row, and stop. Pointing it is the finished pass. **Do not do it for them** and do not write the page you would then be gating.

**4. Do the one unit.** It usually takes one of three shapes:

- **A client wrote in.** Confirm who they are against [clients.md](../clients.md) first — a folder name is not a client, Hoffman is a question rather than a Current client, Cornelia Choe is Alumni, and HubSpot is closed. Then [run-faq](../../skills/run-faq/SKILL.md) for what the FAQ already covers, gated by **If a client writes**, then [author-support-reply](../../skills/author-support-reply/SKILL.md) to draft the reply. You draft in Michael's voice from Michael's own accounts. **You do not send.**
- **A shift or a tenure is changing hands.** That runs off the **PA handoff** page in Notion via [pa-handoff](../../skills/pa-handoff/SKILL.md), not off this page and not off memory. Do not name the next PA or a tenure end date — neither is recorded.
- **This seat's own named leftover.** One of them, taken to a finish.

Facts come from `handbook/` or from Michael's own word. Anything else is **"not recorded"**, said out loud, in the same words this repo already uses for it. If a price comes up, do not recall it — run [place-on-offer-ladder](../../skills/place-on-offer-ladder/SKILL.md) against [offers.md](../offers.md), quote both numbers where the ladder shows two, and say Platinum Major List has no public price.

**5. Run the last gate.** [reviews/last-gate-checklist.md](../../reviews/last-gate-checklist.md), every line, out loud, honestly. Name the unchecked line rather than softening it. Nothing sends because the gate passed — the one thing it unlocks is on [plans/pa.md](../plans/pa.md), and it is a docs pull request after the [COO](../seats/coo.md) has done first QC.

**6. Stop, and write the note below.** Then hand anything external to Michael and finish.

## The note you leave

Where the work is — on the pull request, in the draft, or in the message you hand Michael. Four lines, and nothing more:

- **Where things stand.** One sentence somebody who was not here can act on.
- **The one unit I took**, and where it ended up: in Michael's hands, on a pull request, or stopped on a named lock.
- **What is still open**, each with its actual next step. "Follow up" is not a next step.
- **What I could not answer**, in this repo's own words: not recorded.

Two things make that note worth reading. **Never invent a name, an owner, a date, a figure, or a link to make a line look finished** — an unknown left as an unknown is the useful answer, and a plausible filler reads to the next person as something you checked. And **never quietly drop an item the last note left open**: if it closed, say it closed; if it did not, carry it forward.

No stamps, no status tags, no run identifiers. A person reads this.

- **Never does another seat's job**, and never QCs work this seat wrote.
- **Never touches program GitHub**, stands up a VM or a GKE cluster, installs a local model, or plans this pass around the M5. The M1 is the office; the M5 is the shop and stays parked until Michael says go. Full list: [locks.md](../locks.md).
