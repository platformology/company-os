# Runtime — the guts

Shape: the pick-order and the empty-queue rule already written in [cheap-loop.md](cheap-loop.md) and [run-always-on](../skills/run-always-on/SKILL.md). Public GitHub was searched first; the outside shapes those two pages adapted are credited in [SOURCES.md](../SOURCES.md). This page borrows no new outside shape, so it adds no source row and names no kit.

The map for the whole runtime is `handbook/runtime.md` — in flight. It lands separately, and this page does not wait on it.

This page is one organ of that runtime: **the guts.** The guts are the digestive system. They take what has already been put in front of a seat and turn it into finished work. They are not a task tracker, and this page does not start one.

The bar: Anthony, Jhana, or Bob can sit in an assigned seat, open this page, and know what to do next without asking the PA to invent a task. If that isn't true after one read, this page failed.

## The guts in one line

**An assigned seat takes the next named leftover for its own job and does it — without waiting for the PA to write the work.**

That is the whole organ. The rest of this page is how a seat picks the next unit, and how it knows the pass is done.

## What a leftover is

A **leftover** is a unit of work that is already named in writing, somewhere sourced, and not finished:

- something a previous pass on this seat's job left open and said so;
- a hole this seat's own page or router already names as missing;
- a named corpus gap for this seat's job in [SOURCES.md](../SOURCES.md).

A leftover is found, not invented. If you can't point at the line that names it, it isn't a leftover — it's invented work, which [cheap-loop.md](cheap-loop.md) already bars.

## Picking the next unit — in this order

Assigned seat, one unit at a time. Stop at the first step that gives you something.

1. **Your own leftover.** Open your row in [seat-job-map.md](seat-job-map.md), open the router in that row, and do the leftover named on your own job. Don't ask first, and don't park the pass waiting for the PA to restate it.
2. **Your own named corpus gap.** No leftover on the job? Then learn or improve **that same named job** from a gap already named in [SOURCES.md](../SOURCES.md) — the "empty queue is a failure" rule from [cheap-loop.md](cheap-loop.md), unchanged. Never a new job, a new client, a new offer, or a KPI figure.
3. **Stop, and say the queue is honestly empty.** Only after 1 and 2 both came up dry. Say it plainly and name where you looked. "Honestly empty" is a real answer a seat is allowed to give; looking busy is not.

Then run [last-gate-then-stop](../skills/last-gate-then-stop/SKILL.md) and stop. One unit, one gate, one stop — no second unit "while I'm here," and no fanning one out across seats. See [run-always-on](../skills/run-always-on/SKILL.md).

## Done-check

A pass is done when **one** of these is true:

- a **named leftover is closed**, or
- the **hole is named** — written down as missing, in the place the next seat will look.

Anything else is not done. **Sitting while a named leftover exists is a fail** — the queue wasn't empty; the seat just didn't pick it up.

**Activity is not progress.** A longer plan, a fresh list, a status update about the work, another read-through — none of those close a leftover. These do: a merge on `main`, a page a new hire can run, a leftover closed.

## Hours

The seat's day runs on the token rule: a wake at 8am, then 11, 2, and 5. Four wakes, not twenty-four — **no hourly Grok wakes.** After Michael's go, local does the hours; nothing on this page starts a machine (see [locks.md](locks.md)).

Bot seats run around the clock. Jhana, Bob, and Anthony do not — see [people.md](people.md). A bot seat's pass doesn't wait on a human's clock, and a human seat's job isn't scheduled as if it never sleeps.

## The PA's part

The PA assigns the next leftover **only** when a seat's queue is empty **and** a named leftover still exists somewhere else. That is a pointing job: the PA names which leftover and which seat picks it up.

**The PA does not write the page.** Not the seat's work, not the leftover's output, and not a task invented to cover a gap. Daily work comes off the Do this page, and seats do not invent daily work — [run-do-this](../skills/run-do-this/SKILL.md).

## No new tracker

No Vikunja install. No new board, no queue file, no ticket system in this repo. A leftover lives where it was already named — the seat page, the router, or [SOURCES.md](../SOURCES.md) — and this page adds no second place to look.

**Notion stays the last-gate book.** The gate itself is [reviews/last-gate-checklist.md](../reviews/last-gate-checklist.md), and the Notion pages named in [seat-job-map.md](seat-job-map.md) stay the working record. This page does not re-host either one.

## Not on this page

The guts are one piece of four. The brain, the body, and the wiring are not written here, and neither are growth plans — business, marketing, R&D, timelines, sprints. Those wait until the four pieces work like a person. Don't add them here to make the page look finished.

## Never

- Never sit out a pass while a named leftover exists.
- Never invent a leftover, a new job, a client, a dollar figure, a person, or a price. **KPI Current stays empty** — a 0 is a figure, so it doesn't go in there either. The 18 Aug 2026 extract in [clients.md](clients.md) separately counts 0 Current and 0 Prospect; quote that with its date, and don't move it into the KPI.
- Never take a second unit in the same pass, and never fan one out across seats.
- Leftover-file assigned seats open the leftover already written. Never switch the guts on for a parked seat.
- Never stand up a tracker or a board to hold a leftover.
- Never send without Michael. No program GitHub. See [locks.md](locks.md).
