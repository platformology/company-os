A seat is a function, not a person — [JGalego/TeamAPI](https://github.com/JGalego/TeamAPI) `docs/spec/teamapi-extended-v1.md` puts it directly: "a role can be vacant... independent of whoever currently fills each seat." Each page below keeps that split, and uses the Purpose / Domains / Accountabilities shape from [holacracyone/Holacracy-Constitution](https://github.com/holacracyone/Holacracy-Constitution) `Holacracy-Constitution.md`.

## What "Craft" is

Craft is a **cluster, not a seat**. Ten of the new seats — the four designers and the six writing and editing seats — are craft that no recorded seat owns today. No design owner and no writing owner appears anywhere in this repo, so rather than invent an executive to hang them from, they sit in Craft and say so on their own pages.

Craft has **no owner recorded**, and nobody is acting as one. Digital design leans toward the [CMO](cmo.md); print and book design leans toward the [CCO](cco.md) and the book bench; the writing seats are neither the CMO's (that seat owns positioning and the public offer ladder) nor the Head of Content's (that seat is the librarian). Michael names the real lines. Until he does, "Craft" is the honest answer instead of a guessed reporting line.

## If OpenClaw workspaces land later

`handbook/engine/` does not exist on this branch, so no `engine/workspaces/<slug>/` stub was written for these seats — an empty folder tree for a runtime nobody has installed is worse than nothing. The shape those stubs would take is already described in [runtime-openclaw.md](../runtime-openclaw.md): one workspace per seat, holding the small fixed set of injected files. Ours are already on disk under different names — the body is the voice file, the desk is the first-run ritual, the router is the skill. Whoever adds `engine/` adds the workspace stubs then, one per slug, and points them at the trio that already exists here. Nothing gets installed to make that happen.

Each seat page carries a **Run this** line naming the skill that runs it, and all forty-six seats now have a `run-*` router of their own — the twenty-three new ones being thin routers that say the seat is unassigned and send you back to the seat page. To go the other way — pick a seat, get the skill and the Notion page in one row — open [seat-job-map.md](../seat-job-map.md). For the full list of skills regardless of seat, open [skills/README.md](../../skills/README.md). A router existing for a seat does not fill it: every seat above except COO is still "Not recorded."
